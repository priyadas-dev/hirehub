## Label protocol

HireHub’s 12 classes:  
`engineering`, `data`, `design`, `product`, `marketing`, `sales`, `operations`, `finance`, `healthcare`, `education`, `customer_support`, `hr`.

1. If source `Job Type` maps cleanly → that HireHub class (`TYPE_MAP` in the builder).  
2. Else (Consulting / Biotechnology / Nonprofit / …) → conservative **title + description keyword** rules; first match wins.  
3. Outside taxonomy (building Architecture, Journalism newsroom roles) → **dropped**.  
4. Empty / error extracts / very short text → **dropped**.  
5. Cap **≤28 rows per class** for balance (deterministic by source index).

Labels are **single-annotator / rule-assisted**, not multi-rater gold. Per-class support can be sparse (especially `hr`).

## Disjointness

- Not generated by `generateSyntheticJobCorpus` / classifier enrichment title banks.  
- Not the 12-row `ORIGINAL_JOB_DESCRIPTIONS` micro set (that remains a separate soft check).  
- Do not blend this score into `syntheticBenchmark`.

## Reporting rules

- Report under **`independentBenchmark`** only.  
- Include `n`, provenance, license, accuracy, macroF1, weightedF1, perClass, confusion.  
- Disclaimer when any class has low support.  
- Never claim “real HireHub production accuracy” from this set alone (public multi-employer postings ≠ HireHub DB).
